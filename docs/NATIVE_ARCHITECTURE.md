# Native edition integration contract

Godot 4.6.3, compatibility renderer, native Windows executable. All code in `native/`; preserve the browser edition. Root owns `native/scripts/main.gd` and the UI/integration/save controller. Authors may own separate files assigned below. Avoid class_name on scripts unless necessary; use preload/load + .new(). Warnings-as-errors/inferred Variant issues: explicit types or `=` rather than `:=` for JSON values.

## Content (`native/data/town.json`)

Root object `{version:2, maps:[...], npcs:[...]}`. Map fields `id,name,description,ambience,theme,width,depth,spawn:[x,z],districts:[{id,name,x,z}],paths:[{points:[[x,z]...],width,kind}],objects:[...],npcs:[...],portals:[...],traffic:[...]`. Objects `{id,wordId,x,z,y:0,rotation:0,scale:1,solid:bool,variant?,parentId?,size?:[w,h,d],interactable:bool}`. Explicit placements and generated shelf products carry labels. Default floor y=0. NPC map placements `{id,x,z,route:[[x,z],...],role?}`; NPC global definitions `{id,name,role,color,venue,personality,bio}`. Portals `{id,label,x,z,target,spawn:[x,z],buildingId?,interactionRadius:3}`. Town id `town`; all buildings have an exterior portal and distinct interior with exit to corresponding town door. Preserve existing mission ids as interiors/map destinations where useful (all 12 accessible, no unbuilt placeholders). Additional supermarket, restaurant, post-office, nightlife, school, clinic, workshop, library, hotel, tailor, station, museum, bank venues all populated with gameplay. NPC/venue IDs are stable strings. Data `native/data/vocabulary.json` root `{languages:[...],words:[...categories?]}` exports existing src/data.js (root handles export before others). Use existing word ids; new ids require full 4language entries.

## World (`native/scripts/world.gd`)

Node3D, setup(map:Dictionary, words:Dictionary, language:String, npcs:Dictionary, player_spawn:Array=[]); signals `interaction_requested(kind:String,id:String)` where kind object/npc/portal, `player_moved(position:Vector3)`, `district_changed(id:String)`; methods `set_active(bool)`, `set_language(id)`, `set_labels(bool)`, `get_objects()->Array` (records with instanceId,wordId,name,x,z), `get_player_position()->Vector3`, `set_player_position(pos:Vector3)`, `focus_object(instance_id:String)`, `move_to_district(id:String)`, `set_time(hours:float)`, `get_diagnostics()->Dictionary`. World includes controllable avatar WASD/arrows, sprint Shift, E interaction, mouse camera orbit/rightdrag/zoom, collision, animated walk cycles. Click objects only selects/indicates; E/proximity needed to take/use/talk/enter; do not teleport from noun labels. NPC routines/traffic separate routes; keep solid obstacles and placements valid. Export player node variable `player` if useful, but controller only needs methods above.

## Activities (`native/scripts/activities.gd` + `activity_rules.gd`)

Control with signals `finished(result:Dictionary)` and `closed`; setup(venue_id:String, language:String, level:int, mode:String="work", inventory:Dictionary={}); results `{venue,mode,success,score,xp,coins,items?,summary}`. It fills available screen space; UI integration root adds inside modal container. Use data vocabulary for translations (load res://data/vocabulary.json). Supermarket modes `work` and `customer`; cafe `work` with layered recipes/orders; every interior venue maps to a designed activity. Expose static/pure activity rules for tests. Activity dialogue uses full sentences and increasing difficulty in all4languages. Missing venue falls back to authored expedition/task appropriate not unimplemented placeholder. Setup venue_id uses map.id, including all12 old quest ids.

## Story (`native/data/story.json` + `native/scripts/language.gd`)

Root `{quests:[...],dialogues:{npcId:[...]},challenges:{id:{...}}, grammar:[...]}`. Quests use original12 ids and requires graph, fields `{id,title,npcId,mapId,requires,description,reward:{xp,coins},steps:[...]}`. Steps typed `{type:"talk"|"collect"|"use"|"activity"|"deliver"|"challenge",mapId,wordId?,quantity?:1,npcId?,activity?:map_id,mode?:"work",challengeId?,text,dialogueId?}`. Missions contain travel, spatial inventory tasks and full sentence challenges rather than nouns-only. Root controller handles each typed objective and tracks ordered stage. Object items should be present and obtainable in current map; tasks `use` also require E/proximity. Multi-step unique narratives. Dialogue entry `{id,title,english,lines:[{speaker,text:{de,ja,es,zh},english}],challengeId?,questId?}`. Challenge `{id,prompt,grammar,context,tier,translations:{de:{answer,reading?,accepted?:[],tokens?:[],choices?:[3fullsentences],explanation},...}}`. Challenge should provide native answer+reading and pedagogical English explanation; root can offer choice, sentence ordering, typing according to level. `language.gd` RefCounted pure helper static normalize_answer(text:String)->String, check_answer(answer:String, challenge:Dictionary, language:String)->bool, get_challenge(id:String, level:int=1)->Dictionary, validate_content()->Array. ROOT controls quest state/rewards. Give quest stages for all12missions, every venue and dialogues level1/2/3 variety.

## Audio (`native/scripts/ambience.gd`)

Node, setup(), play_environment(id:String), set_enabled(bool), play_effect(id:String), set_volume(value:float), optional get_diagnostics. Procedural original ambience or authored WAV embedded with profiles every map/venue. Default 0.3 volume, user toggle. Stop previous loops crossfade cleanup, suspend/restore on pause if needed.

## Saves and UI (root)

Native saves user://progress-v2.json per language; native avatar position/map, discoveries, mission stages, inventory, XP/coins, work statistics, grammar records. Persistent unlocked quests; each NPC can assign tasks. Main menu Continue/New game/language/audio + native standard exit/fullscreen. Town guide/travel lists distinct maps and building gameplay; no inaccessible locked maps needed for exploring. All world object types deduped by wordId in “Objects here”, with instance count and nearest location; actual instance list retained internally. No list click grants quest progress or teleports; player walks physically. Loading overlay on every transition; NPC dialogue modal, inventory/wordbook, journal, sentence-composer, activities, settings. Existing German/Japanese/Spanish/Chinese kept.
